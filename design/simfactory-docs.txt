HOW THIS DOCUMENT WAS PRODUCED
------------------------------
Five independent agents crawled disjoint (and, for the most safety-critical
area, deliberately OVERLAPPING) parts of the source:
  - CLI surface / dispatch / options       (lib/sim.py, simenv.py, simopts.py)
  - On-disk simulation layout, pass 1       (simrestart.py, restartlib.py, simlib.py)
  - On-disk simulation layout, pass 2       (independent re-derivation of the same)
  - Machine DB / config / INI parser        (simdb.py, pyini.py, simdt.py, mdb/, etc/)
  - Build/sync/remote/archive/subs/distribute

The two on-disk-layout passes were run independently and AGREE on every load-
bearing fact (directory templates, the active-restart symlink mechanism, the
property model, the lifecycle). Single-source uncertainties raised by one agent
were resolved by another, and the highest-value claims (simenv path constants,
the "output-%04d" format, the symlink semantics, the skeleton directory set,
the simulation-id / PBS-name format strings) were additionally re-verified
directly against source. Every nontrivial claim carries a file:line anchor;
literal strings (format strings, filenames, key names, delimiters) are quoted
verbatim. Items that could not be fully resolved are marked "UNCERTAIN".

Anchors are relative to /home/max/src/simfactory2. "BuildPath(a,b)" == "a/b"
(os.sep.join; simlib.py:761-767).

================================================================================
1. WHAT SIMFACTORY IS
================================================================================
SimFactory is the command-line tool the Cactus computational framework / the
Einstein Toolkit uses to configure, build, submit, manage, and archive numerical
simulations across many HPC clusters and workstations. A single machine database
(MDB) describes each cluster (queues, submit commands, paths, hardware), and
SimFactory uses it to:
  - build Cactus "configurations" (compiled executables) from option lists,
    thorn lists, run scripts and submit scripts;
  - lay out a per-simulation directory tree on disk, with numbered "restarts";
  - generate batch submit scripts and run scripts via @VAR@ template substitution;
  - submit/queue/run jobs, chain restarts to extend walltime, recover from
    checkpoints, and clean up;
  - sync the source tree to remote machines, run remotely over ssh, and archive
    finished simulations to tape/grid stores.

Runtime code is in lib/*.py (Python 2/3 compatible; several modules use
`from __future__ import print_function`). The doc generators under
doc/userguide/ are Python-2-only build tooling, not part of the CLI.

================================================================================
3. COMMAND DISPATCH ARCHITECTURE
================================================================================
Two-level dispatch.

Level 1 (sim.py): maps each command name to one of five "binary" modules and
calls that module's main().
  - known_binaries = ['sim-sync','sim-build','sim-manage','sim-info','sim-util']
    (imported via __import__ by literal hyphenated name; sim.py:40-52).
  - known_commands seeded {'sync':'sim-sync','build':'sim-build'} (sim.py:47),
    then extended from each binary's module-level `known_commands` list
    (buildKnownCommands, sim.py:57-65) -> dict {command -> owning binary}.
  - CommandDispatch (sim.py:88-107):
        command = OptionsManager.args[0]
        if command == 'help': PrintHelp(); sys.exit(0)   # 'help' pseudo-command
        simenv.COMMAND = command
        args.pop(0)
        if command not in known_commands: fatal("unknown command ...")
        sys.modules[binary].main()
  - If option --remote is set, sim.py short-circuits to RemoteExecute (section 18)
    and does NOT dispatch locally (sim.py:139-143).
  - No args -> PrintHelp(); exit 0 (sim.py:118-120).
  - Startup banner prints "defs: <path>" (simenv.cdb) and "defs.local: <path>"
    (simenv.udb) when present (sim.py:126-129).

Level 2 (each binary): re-derives the command from simenv.COMMAND, replaces '-'
with '_', and invokes the implementing function. Idioms differ slightly:
  - sim-build:  main() RequireMachine(); mkdir CONFIGS_PATH; if first arg=='build'
                pop it else append 'build'. CommandDispatch treats ANY unknown
                subcommand token as a config name and falls through to
                command_build() (sim-build.py:395-411,466-488). No "unknown
                command" error under `sim build`.
  - sim-info:   command = COMMAND or args[0]; unknown -> fatal; calls
                globals()[name]() where functions are BARE-named (list_machines,
                not command_list_machines) (sim-info.py:241-274).
  - sim-manage: RequireMachine(); CommandDispatch via exec("command_%s()" % name);
                unknown -> PrintHelp + exit 1 (sim-manage.py:361-398).
  - sim-sync:   no CommandDispatch; main() runs sync directly, skipping any arg
                literally 'sync' (sim-sync.py:204-281).
  - sim-util:   mkdir CONFIGS_PATH; CommandDispatch via exec("command_%s()")
                (sim-util.py:34-53,262-270). Does NOT RequireMachine globally;
                individual commands call it as needed.
  Aliases are implemented as duplicate wrapper functions: list-sim -> list_sim()
  -> list_simulations() (sim-info.py:76-77); list-conf -> list_conf()
  -> list_configurations() (sim-info.py:237-238).

5. THE OPTION SYSTEM
================================================================================
Options are NOT hard-coded; they are declared in etc/options/*.ini and turned
into optparse options at runtime (simopts.py).

5.1 Mechanism
  - OptionManager(OPTIONS_PATH) (simopts.py:35); Discovery() builds one
    pyini.IniParser per *.ini (simopts.py:153-167).
  - usedGroups starts ["common"] (simopts.py:39); sim.py adds the 5 groups.
  - Build() (simopts.py:217-230) creates optparse.OptionParser with a custom
    option_class TypeNonNull, adds built-in callbacks, adds each group ("common"
    on the parser, others as an OptionGroup "Options from <group>"), then
    parse_args() -> OptionsManager.options (values), OptionsManager.args
    (leftover positionals = command + command args).

5.2 INI option schema (one [section] = one option) (AddOption, simopts.py:245-304)
    long      : long flag (required), e.g. "--verbose"
    short     : short flag, e.g. "-j"
    alias     : alternate name; optparse dest is set to the alias (so --cores
                writes options.procs)
    desc      : help text
    negatable : "yes" generates --[no]X visible plus hidden --noX and --no-X
                (cannot combine with a short option -> fatal, simopts.py:251-252)
    arg       : "yes" => takes an argument; "no" => store_true flag
    argtype   : 'nonnull' (custom; rejects empty/whitespace), 'int', 'string'
    argformat : metavar shown in help
    multiarg  : "yes" => action="append" (repeatable; value is a list)
    default   : default value
  Options are added by eval("op.add_option(%s)" % optstring) (simopts.py:292-342).
  *** BUG: in the arg=yes branch the code checks `if 'defeult' in sdict`
     (misspelled, simopts.py:271), so `default=` is SILENTLY IGNORED for all
     argument-taking options. Defaults only take effect for boolean flags
     (simopts.py:278-280) and via the negatable meta option. Practical effect:
     the ini defaults for --debugger ("totalview") and --select-tests ("all")
     do NOT apply at the OptionsManager level; effective default is None unless
     downstream code substitutes a value. ***

5.3 Built-in (non-ini) callback options (BuildBuiltins, simopts.py:182-215)
    --define <k> <v>      Macros[k]=v (leading "@" stripped). Feeds @k@ substitution.
    --mdbkey <k> <v>      MDBKeys[k]=v -> written into EVERY machine section at load.
    --substitute <a> <b>  appends (a,b) to Substitutions (regex content sub).
    --replace <s>         appends to Replacements ("KEY=VALUE" line replace).
    --append <s>          appends to Appends ("KEY=VALUE" line prepend).
  Plus optparse's -h/--help.

5.4 Introspection helpers
    HasOption(o)        getattr(options,o) is not None
    GetOption(o)        getattr(options,o,None)
    UpdateOption(o,v)   setattr (used to inject parfile/procs/walltime positionals)
    RawOptionDefined(o) PREFIX-scans raw sys.argv for "--<o>" (so "--optionlistx"
                        matches "optionlist"); detects EXPLICIT user options
    IsNegated(o)        scans raw argv for "--no<o>"; NOTE it does NOT detect the
                        "--no-<o>" spelling
    BuildOptionString() re-serializes parsed options for remote forwarding; only
                        re-emits RawOptionDefined options (defaults not propagated)

7. THE INI PARSER (lib/pyini.py)
================================================================================
A custom, line-oriented parser (NOT ConfigParser). class InternalParser.Parse()
(pyini.py:658-800); each line is .strip()'d, then matched in this order:

  (a) blank -> ignored.
  (b) comment: line[0] in '#' or ';' (pyini.py:687). FULL-LINE only -- a '#'/';'
      not at column 0 is not a line comment. Full-line comments accumulate as the
      LeadingComment of the next key/block.
  (c) if in block mode: look for the block terminator.
  (d) section header: r'\[(\S+)\]' (pyini.py:661). No whitespace allowed inside
      brackets (else fatal "no whitespace allowed in section identifier").
  (e) block start: r'(\S+)\s*=\s*<<(\w+).*$' (pyini.py:667). Tried before the
      plain key regex on purpose.
  (f) key=value: r'(\S+)\s*=\s*([^#]*)[#]?.*$' (pyini.py:664). key = a run of
      non-whitespace; value = up to the first '#'.
  (g) else -> fatal syntax error.

7.1 Keys
  - A key is \S+ (may contain '/', '+', '.', etc. -- e.g. machine key "flop/cycle").
    Whitespace before '=' -> fatal "no whitespace allowed in key identifier".
  - DUPLICATE keys within a [section] are FATAL ("duplicate key %s",
    pyini.py:720-722, 786-788). NOTE: this check fires only inside named sections;
    GLOBAL (pre-section) duplicate keys are NOT caught and silently overwrite.

7.2 Values / inline comments / quoting
  - Inline comment: value stops at the first '#'. Only '#' terminates an inline
    value, NOT ';'.
  - Trailing whitespace stripped (OriginalValue = value.rstrip()).
  - Quoting (InterpretQuotes, pyini.py:260-276): if the value starts with ' or ",
    it must match the matched-quote regex; the inner text becomes the value
    (IsQuoted=True), letting it contain '#'/spaces. A trailing " #comment" after
    the close quote is allowed. Malformed quote -> fatal. Backslash escapes are
    accepted by the regex but NOT unescaped (backslashes are kept literally).

7.3 Block (heredoc / multi-line) values
        KEY = <<IDENT
        ...lines...
        IDENT
  - IDENT is \w+ (need NOT be "EOT"; e.g. <<EOF, <<EOT both work). Terminator is
    a line containing only IDENT (r'\s*IDENT\s*$', rebuilt dynamically).
  - Body lines appended verbatim with trailing newline.
    *** QUIRK: only the FIRST body line is passed through inline-comment
       stripping (#/; from StripInlineComment); subsequent lines are verbatim
       (pyini.py:703-706). ***
  - EOF before terminator -> fatal "Runaway <<%s block...".
  - Callers may convert a block value to a LIST via ConvertToList() (splits on
    "\n"). This is how config-DB list keys (sync-sources etc.) and list
    properties are formed.

7.4 Sections & globals
  - Keys before any [section] are GLOBALS (parser.Globals). After a header, keys
    go into parser.Section[name]. Section and per-section key order are preserved.
  - NO %(name)s interpolation, NO include directive in pyini. @VAR@ substitution
    is an entirely separate later pass (section 11); pyini stores @USER@ etc. as
    literal text.

7.5 Merge engine (IniParser.UpdateFromIni, pyini.py:64-124) -- see section 10.4.

7.6 Syntax checker (IniSyntaxChecker, pyini.py:279-456)
  Validates an INI against a "syntax file" (itself an INI; section 8). For each
  section (= a permitted key) it reads necessity/type/pattern/default/example/
  description. It:
    - injects defaults for missing keys (SetSectionDefaults);
    - REJECTS any key in the target not present in the syntax file (fatal "found
      invalid keys");
    - enforces required keys, type coercion (int/double/float), and pattern match.
  The fatal handler can be softened (lambda) -- simdb uses this to drop incomplete
  udb-only machines instead of aborting.

8. THE MACHINE DATABASE (mdb/machines/*.ini)
================================================================================

8.1 Physical layout
  - One machine per file mdb/machines/<anything>.ini (only ".ini" loaded;
    simdb.py:94). The filename need not match the section.
  - Each file MUST contain EXACTLY ONE [section]; the section name IS the machine
    name/key (e.g. [mike], [frontera], [generic]). >1 or 0 sections -> ValueError
    (simdb.py:101-105). The same section in two files -> "defined twice"
    (simdb.py:107-108).
  - Standard pyini KEY=VALUE and <<EOT/<<EOF blocks. Values may carry @VAR@
    placeholders, e.g.:
        sourcebasedir = /home/@USER@                 (generic.ini:28)
        make          = make -j@MAKEJOBS@            (generic.ini:32)
        submit        = sbatch @SCRIPTFILE@ 2>&1     (mike.ini:47)
        getstatus     = squeue -j @JOB_ID@           (mike.ini:48)

8.2 AUTHORITATIVE key catalog: etc/syntax/mdb-syntax.ini
  Every recognized machine key is a [section] there; any key NOT listed is
  REJECTED at load. (etc/syntax/description-syntax.ini is the meta-schema that
  mdb-syntax.ini itself is validated against, on every load: simdb.py:84-85.)
  Each entry: key -- necessity / type / default / pattern -- meaning.

  Group "machine" (descriptive):
    nickname     req string  ^[a-zA-Z0-9_+-\.]+$    short nickname
    name         req string                          full human name
    location     req string                          geographic location
    description  req string                          free text
    webpage      opt string                          URL
    status       req string  ^(personal|experimental|production|storage|outdated|
                                trampoline)$
                 (personal=permission only; experimental=may not work;
                  production=works OOTB; storage=data only; outdated=do not use;
                  trampoline=tunneling only)

  Group "access":

9. MACHINE DETECTION (LOCAL vs REMOTE)
================================================================================

9.1 Local machine name -- simlib.GetMachineName() (simlib.py:77-124):
  1. --machine option wins outright.
  2. else machineName = GetHostNameAlias().
  3. A machine matches if section name == machineName OR entry.hostname ==
     machineName OR aliaspattern regex matches machineName.
  4. 0 matches -> warning "Unknown machine name %s", returns None.
  5. >1 matches (shared login nodes): disambiguate by keeping machines whose
     (subbed) sourcebasedir is a prefix of the real CACTUS_PATH. Exactly one
     left -> use it; else warning "Could not identify machine ...".

  GetHostNameAlias() (simlib.py:17-54), in order:
    1. --hostname option, 2. ~/.hostname file contents, 3. shell `hostname` then
    socket.gethostbyname_ex (prefer the first dotted name, "localhost" filtered).

9.2 Local entry -- simenv.py:128-133. If unknown, RequireMachine() fatals with a
  hint: "Please use 'sim setup' to create a local machine entry from the generic
  template." (simlib.py:1075-1078).

9.3 Local vs remote
  - There is NO "local" flag in the MDB; the same entries describe a machine
    whether you are on it or ssh-ing to it.
  - LOCAL = the machine matched for the current host; commands run directly.
  - REMOTE = chosen with --remote/--remotemachine; SimFactory ssh-es to it,
    using access keys hostname/user/sshcmd/sshopts/localssh*/trampoline/iomachine/
    rsync*. (Section 18.)
  - The "generic" machine describes a workstation: submit is a local nohup/exec,
    getstatus is `ps`, stop is `pkill` (generic.ini:38-47) -- no batch system.

     soft-dropped). Treat "scratchdir" as a legacy/suspect example. ***

10.4 Load order & merge semantics
  1. Validate mdb-syntax.ini against description-syntax.ini.
  2. Load every mdb/machines/*.ini (UpdateFromIni(path, importSections=True)).
  3. Load cdb; ConvertBlocks() turns global blocks into lists.
  4. If udb: merge into MachineParser (importSections=True) AND ConfigParser.
  5. Apply --mdbkey overrides: MachineParser.UpdateFromDict(MDBKeys) writes each
     key into EVERY machine section (simdb.py:131).
  6. SetSectionDefaults(): fill missing keys from mdb-syntax.ini defaults
     (envsetup=":", sshcmd="ssh", sshopts="-Y", num-threads=1, queue="NOQUEUE",
     maxwalltime="8760:00:00", make="make", efficiency=0.1, memory=0, min-ppn=1...).
  7. If udb: syntax-check machines; udb-only machines that fail are DROPPED with a
     warning; non-udb machines are hard-checked (simdb.py:140-148).

  UpdateFromIni (pyini.py:64-124) precise rules:
    (a) GLOBAL keys present in both: if self's value is a list, the incoming value
        is converted to a list and the incoming items are placed FIRST, existing
        AFTER (accumulate); else scalar overwrite. Incoming globals not already in
        self are skipped.
    (b) named sections: if importSections, create if absent; if present, every
        incoming key OVERWRITES self's. (This is how a [mike] block in
        defs.local.ini overrides mdb values.)
    (c) special "default" section: applied to EVERY existing section but ONLY
        where the key is not already present (fill-only fallback).

10.5 Effective precedence for a machine key (highest first)
  1. --mdbkey KEY VALUE (every section; applied after udb)
  2. dedicated run-time options via GetMachineOption (--queue/--allocation/--ppn/
     --walltime/etc.) -- override at use time without touching the DB
  3. per-machine [<machine>] section in defs.local.ini
  4. the machine's own mdb/machines/<m>.ini value
  5. [default] section of defs.local.ini (fill-only)
  6. mdb-syntax.ini defaults (fill-only)
  (List-valued GLOBAL config keys accumulate rather than override.)

  NOTE: lib/dt/defaults.ini, defaults-silent.ini, machine-override.ini are
  DECISION TREES for `sim setup` (section 20), NOT part of this runtime layering.


================================================================================
11. THE @VAR@ SUBSTITUTION ENGINE (lib/simsubs.py)
================================================================================
class DefineDatabase. Delimiter is the AT sign: @NAME@. Applied to selected
machine-entry strings (basedir, sourcebasedir, sshopts, envsetup) and to
optionlist/runscript/submitscript/parfile CONTENTS at build/submit/run time.
pyini does NOT do this; it is a separate pass.

SubAll() (simsubs.py:167-216) loops to a fixpoint, each pass applying:
  (a) Plain macro:  @NAME@ -> value (literal string replace). Nested @VAR@ in
      values resolve because of the loop.
  (b) Expression:   @( EXPR )@  (regex r"@\(([^@]+)\)@"). EXPR is Python eval'd
      in a namespace providing only ifthen(). Ternary sugar: if EXPR contains '?'
      it is rewritten to ifthen(cond,a,b) (TransformTernary). Word operators are
      translated: ne->!=, eq->==, gt->>, lt-><, gte->>=, lte-><=. More than two
      '?' -> fatal. ifthen swallows eval errors and returns the false-value.
      Real example (frontera.sub:6):
        #SBATCH @("@CHAINED_JOB_ID@" != "" ? "-d afterany:@CHAINED_JOB_ID@" : "")@
  (c) Environment:  @ENV( NAME )@  -> os.environ[NAME]; missing -> fatal.
  (d) Regex substitutions (from --substitute + config-DB "substitutions"):
      (pattern, replacement) with "@1@" -> backreference \1, re.MULTILINE.
  (e) Pattern substitutions from AddDefine/AddSubstitution/AddReplacement/AddAppend.
  Fixpoint exit strips the literal marker "=SIMFACTORY-PROTECTED=".

Content-editing helpers (used to force values into option lists / parfiles):
  AddDefine(var,value)       pattern r"@var@" -> value
  AddSubstitution(var,value) raw regex pattern -> value ("@1@" -> \1)
  AddReplacement(var,value)  replaces the whole line  r"^[ \t]*VAR[ \t]*=.*$"
                             with "=SIMFACTORY-PROTECTED=VAR = value"
  AddAppend(var,value)       r'^[ \t]*VAR[ \t]*=[ \t]*(.*?)[ \t]*$' ->
                             "=SIMFACTORY-PROTECTED=VAR = value \1" (PREPEND)
  The PROTECTED marker prevents re-matching during the loop and is stripped at end.
  CLI feeds: --define/--replace/--append/--substitute (split on first '=').

The COMPLETE @VAR@ name set (submit phase simrestart.py:629-696; run phase
1138-1203; each new_properties[KEY] becomes @KEY@):
  @SOURCEDIR@ @SIMULATION_NAME@ @SHORT_SIMULATION_NAME@ @SIMULATION_ID@
  @RESTART_ID@ @RUNDIR@ @SCRIPTFILE@ @SUBMITSCRIPT@ @EXECUTABLE@ @PARFILE@
  @HOSTNAME@ @USER@ @EMAIL@ @MACHINE@ @NODES@ @PROCS_REQUESTED@ @PPN@ @NUM_PROCS@
  @NODE_PROCS@ @PROCS@ @NUM_THREADS@ @PPN_USED@ @NUM_SMT@ @MEMORY@ @CPUFREQ@
  @ALLOCATION@ @QUEUE@ @WALLTIME@ @WALLTIME_HH@ @WALLTIME_MM@ @WALLTIME_SS@
  @WALLTIME_SECONDS@ @WALLTIME_MINUTES@ @WALLTIME_HOURS@ @SIMFACTORY@
  @CONFIGURATION@ @FROM_RESTART_COMMAND@ ("" or "--from-restart-id=N")
  @CHAINED_JOB_ID@ @RUNDEBUG@ (1/0) @DEBUGGER@ @MAKEJOBS@ @JOB_ID@ @EXECHOST@
  @BASEDIR@
  *** TYPO: "@QEUEUE@" appears in some mdb script(s) (a misspelling of @QUEUE@);
     it will NOT be substituted and leaks literally. Fix during port. ***

12. OPTIONLISTS / RUNSCRIPTS / SUBMITSCRIPTS (mdb/)
================================================================================
Resolution (bare names from machine keys; pattern [^/]$):
    optionlist   -> mdb/optionlists/<name>.cfg     (simlib.py:783-784)
    runscript    -> mdb/runscripts/<name>.run      (simlib.py:826-827)
    submitscript -> mdb/submitscripts/<name>.sub   (simlib.py:823-824)
    thornlist    -> resolved under ETC_PATH         (simlib.py:786-789)
  via GetCactusFile (simlib.py:1012-1073): if the value is a path that exists use
  it; else try cwd/<value>, then <base>/<option>s/<value> (folder name = option
  pluralised). Fatal if unreadable when required.

12.1 OptionList (*.cfg): Cactus build option lists (NOT pyini). Plain
  "NAME = value" + "# comment" lines. Passed through the substitution/replacement
  engine before use. Carries CPP/CC/CXX/F90/LD, *FLAGS families, DEBUG/OPTIMISE/
  PROFILE/WARN/OPENMP toggles, VECTORISE*, etc. The first line is a VERSION date
  string; changing VERSION forces a full reconfigure+rebuild (section 16).

12.2 RunScript (*.run): a bash template executed on the compute node to launch
  Cactus. @VAR@ tokens. generic.run does:
    cd @RUNDIR@-active; export CACTUS_NUM_PROCS/NUM_THREADS/OMP_NUM_THREADS;
    launch @EXECUTABLE@ -L 3 @PARFILE@ (serial or mpirun -np @NUM_PROCS@);
    honors @RUNDEBUG@ to run under gdb.

12.3 SubmitScript (*.sub): a batch submit template. SLURM example (frontera.sub):
    #SBATCH -A @ALLOCATION@ / -p @QUEUE@ / -t @WALLTIME@ / -N @NODES@ -n @NUM_PROCS@
    #SBATCH @("@CHAINED_JOB_ID@" != "" ? "-d afterany:@CHAINED_JOB_ID@" : "")@
    #SBATCH -J @SHORT_SIMULATION_NAME@
    #SBATCH -o @RUNDIR@/@SIMULATION_NAME@.out
    #SBATCH -e @RUNDIR@/@SIMULATION_NAME@.err
    cd @SOURCEDIR@
    @SIMFACTORY@ run @SIMULATION_NAME@ --basedir=@BASEDIR@ --machine=@MACHINE@ \
        --restart-id=@RESTART_ID@ @FROM_RESTART_COMMAND@
  KEY DESIGN POINT: the submit script re-invokes `sim run`, which then substitutes
  the run script and execs the binary. The queue stdout/stderr filenames are
  defined HERE in the template (e.g. @RUNDIR@/@SIMULATION_NAME@.out), NOT in the
  Python; the generic (workstation) submitscript has no scheduler directives.

12.4 Substitution timing: submitscript content subbed with the submit-phase
  property set (simrestart.py:705); runscript content with the run-phase set
  (simrestart.py:1209+). The two phases define slightly different @VAR@s.

14. SIMULATION LIFECYCLE
================================================================================
Commands: create, submit, run, run-debug, interactive, stop, archive, cleanup,
get-output-dir, show-output, create-submit, create-run, purge (sim-manage.py:21-22).

14.1 create() (simrestart.py:1303-1466) -- one-time setup, NO restart yet
  Steps:
   1. Validate parfile (empty "" is the testsuite sentinel).
   2. configuration = GetConfiguration() (default sim[-debug|-optimise|...]).
      configPath = CONFIGS_PATH/<configuration>.
   3. GetExecutable() (restartlib.py:477-503):
        exe          = CACTUS_PATH/exe/cactus_<configuration>  (FATAL if missing)
        submitScript = configPath/SubmitScript (None if absent)
        runScript    = configPath/RunScript    (FATAL if absent)
      optionlist = configPath/OptionList.
   4. config_id = configPath/CONFIG-ID (default 'no-config-id');
      build_id  = configPath/BUILD-ID  (default 'no-build-id').
   5. CreateRestartSkeleton -> (BaseDir, SimulationDir, InternalDir, CacheDir).
   6. CreateSimulationId (section 13.8).
   7. Write SIMFACTORY/properties.ini (section 15), CreateInternalDirs.
   8. Copy executable via CopyFileWithCaching(exe, exedir, CACHE/exe) + chmod +x.
   9. Substitute and write OptionList -> cfg/, SubmitScript -> run/ (or property
      "None"), RunScript -> run/, parfile -> par/ (or "" if no parfile).
  10. Optional --datadir copytree into SIMFACTORY/data.
  NOTE: create() copies into the SIMULATION-level SIMFACTORY/. submit()/run() make
  a SECOND, freshly substituted copy into the RESTART-level dir. The 'executable'
  property always points at the simulation-level SIMFACTORY/exe copy.

14.2 submit() (command_submit -> userSubmit -> submit, simrestart.py:333-828)
  - initRestart(): if no sim exists, create() it; opportunistically cleanup a
    stale active restart whose job status is 'U'; assign a new restart id and
    create output-NNNN/ + output-NNNN/SIMFACTORY/.
  - Build the submit-phase @VAR@ property set (nodes/procs/ppn/queue/allocation/
    walltime/pbsSimulationName/chainedjobid/...); Save() restart properties.ini.
  - Write substituted SubmitScript to InternalDir, chmod +x; copyTestsuiteData if
    testsuite.
  - makeActive() (create the -active symlink) UNLESS this is a chained presubmit.
  - Run machineEntry.submit; mark("simulation"); parse job id via
    machineEntry.submitpattern (extractJobId); store property 'jobid' ("-1" =
    failed/unknown).
  - CHAINING: if the sim is already active, chain the new submission onto the
    current max job id (preSubmit; not made active). AUTO walltime chaining: if
    requested walltime > maxwalltime, presubmit ceil(walltime/maxwalltime)
    additional restarts, each chained onto the previous job id (simrestart.py:800-826).

14.3 run / run-debug (command_run, sim-manage.py:204-241)
  - With --restart-id: submitRun() loads that restart, optionally finishes the
    from-restart-id, makeActive(); FATAL if no active dir; then run().
  - Without: userRun() builds a fresh restart's properties (no submit), Save()s,
    makeActive(), then fork()s and tees stdout/stderr to <Sim>.out/<Sim>.err while
    running run().
  run() (simrestart.py:1081-1295):
    - assert IsActive(); PrepareCheckpointing(recover_id) (14.6) sets property
      'checkpointing' "yes"/"no".
    - create working dir RestartDir/<parname>.
    - .rpar handling: copy .rpar into RestartDir, chmod +x, execute it to generate
      the .par, read that; else read the stored parfile.
    - substitute parfile, write to <RestartDir>/<basename>.par; Save() properties.
    - write RunScript to InternalDir, chmod +x.
    - os.chdir(RestartDir); ExecuteReplaceCommand (exec the run script / make
      testsuite).

14.4 marks / timestamps (simrestart.py:36-97)
  mark(label) writes "%s\n" % time.time() into InternalDir/<label>. Labels used:
  "timestamp" (default; written by finish()) and "simulation" (after submit).
  CleanupRestarts uses them to throttle automatic cleanup (skip sims < 60s old;
  re-clean only every 30s; restartlib.py:151-199). A legacy "<label>-<timestamp>"
  filename form is also recognized on read/clear.

14.5 cleanup / finish (simrestart.py:1630-1827)
  cleanup() == finish(allowForce=True). finish() DEACTIVATES a restart:
    - mark() (timestamp); no-op if no -active symlink.
    - refuses if Properties.machine != local machine.
    - leaves the restart alone if job status is 'E', or != 'U' without --force.
    - if force: stop() the job first.
    - removes the output-NNNN-active symlink (os.unlink).
    - chmod TERMINATE to drop group/other write bits.
    - deletes half-written checkpoints: find ... -name *.chkpt.tmp.it_*.* -exec rm -rf.
    - Formaline tarball DEDUP: for every *.tar.gz >= 1000 bytes, scan previous
      output-%04d dirs (descending); if an identical file (filecmp.cmp) exists,
      replace this one with a HARD LINK via a .tmp rename
      (oldpath = "%s/output-%04d/%s" % (SimulationDir, rid, f); simrestart.py:1797).
  done() just closes the log.

14.6 recovery / checkpointing (PrepareCheckpointing, simrestart.py:160-267)
  - Recover source = 'from-restart-id' property if set, else max_restart_id;
    default recovers from RestartID-1.
  - GetCheckpointFiles(restore_dir): find <workdir> -name *chkpt.it_*. Each is
    HARD-LINKED into the current restart at the corresponding path (restore_dir
    string-replaced by RestartDir), falling back to copy. No checkpoint files ->
    recovery disabled (returns False).

14.7 Job status & state (queried LIVE, not stored)
  GetJobStatus (restartlib.py:327-416) runs machineEntry.getstatus and matches the
  output against the machine's *pattern regexes, returning one of:
    'R' running, 'Q' queued, 'H' holding, 'U' unknown (not in queue),
    'E' in-queue-but-status-unknown.
  list-simulations maps these to ACTIVE (RUNNING/QUEUED/PRESUBMITTED/FINISHED) /
  ERROR / INACTIVE (sim-info.py:130-141).

14.8 stop (simrestart.py:1468-1518)
  If TERMINATE exists and not --force: write the single char '1' into TERMINATE
  (graceful) then finish(). Else run the machine 'stop' command (forced; finish
  removes the symlink). NOTE: TERMINATE is CREATED by the running Cactus job
  (TerminationTrigger), not by create/submit; SimFactory only writes "1" into it
  and tightens its permissions.

14.9 archive (simrestart.py:1830-1840) -- section 19.

14.10 purge -> trash() (simrestart.py:1868-1911)
  FATAL if any restart has a queued/holding/running job. Creates basedir/TRASH,
  then shutil.move(SimulationDir, TRASH/<simulationid>). The WHOLE simulation dir
  is moved (nothing deleted outright; TRASH is not auto-emptied).

14.11 get-output-dir: prints RestartDir for the requested/max restart id (writes
  nothing). show-output: read-only; live-tails via machine stdout/stderr commands
  when running, else reads <Sim>.out/.err and
  <RestartDir>/<parname>/formaline-jar.txt.

15. THE PERSISTED STATE MODEL (properties.ini)
================================================================================
Format: an INI with a SINGLE section literally "[properties]"
(SimProperties.IniSection='properties', simproperties.py:13). File always named
"properties.ini". Each AddProperty sets an object attribute AND writes the key;
Save() rewrites the whole file (pyini GetIniAsString). Block (list) values are
written terminated by "EOT".
  *** QUIRK: AddProperty's `if value is list:` (simproperties.py:66) is an
     identity test that is essentially always False, so list values are not
     actually stored as blocks as intended. ***

Two property files:
  - SIMULATION level: <Sim>/SIMFACTORY/properties.ini      (written by create())
  - RESTART level:    <Sim>/output-NNNN/SIMFACTORY/properties.ini
                      (written by submit()/run(); inherits the sim-level contents
                       because it is initialized by loading the same file)

Keys at CREATE (simrestart.py:1373-1449):
  machine, simulationid, sourcedir, configuration, configid, buildid, testsuite,
  select_tests (only if --testsuite), executable, optionlist, submitscript (or
  "None"), runscript (or "None"), parfile (or "").

Keys added at SUBMIT (rr dict, simrestart.py:708-786):
  nodes, procsrequested, ppn, numprocs, nodeprocs, procs, numthreads, ppnused,
  numsmt, queue, allocation, hostname, user, memory, cpufreq, pbsSimulationName,
  walltime, chainedjobid, jobid; plus from-restart-id (if --from-restart-id).
  (userRun writes the same proc/host keys minus queue/allocation/walltime/
  chainedjobid; run() also sets 'checkpointing'.)

Job id storage (GetJobId, simrestart.py:1842-1858): prefers the 'jobid' property;
falls back to reading 'jobid' from SIMFACTORY/job.ini (legacy). '-1' = unknown.

NOTE: on-disk property KEYS are lowercase (submitscript, jobid; pbsSimulationName
is mixed-case as shown). The UPPERCASE names (SIMULATION_NAME, RESTART_ID, RUNDIR,
...) are @VAR@ substitution variables for templating, NOT property keys.

16. BUILD SUBSYSTEM (lib/sim-build.py)
================================================================================
On-disk: configs/<configName>/ under CONFIGS_PATH (= CACTUS_PATH/configs).
  Subfolders (created): ['bindings','build','config-data','lib','scratch'].
  Files managed in configBase:
    properties.ini  (+ no .old)         -- build flags/state (SimProperties)
    OptionList      + OptionList.old
    SubmitScript    + SubmitScript.old
    RunScript       + RunScript.old
    ThornList       + ThornList.old
    config-data/cctk_Config.h           -- presence => "complete config"
    config-data/make.thornlist          -- removed to force rebuild
  If configBase exists but has no properties.ini -> FATAL "not a SimFactory
  configuration ... delete it and run sim build again".

Flow (command_build -> PrepConfiguration -> BuildConfiguration/BuildVirtual):
  - configList = args or [GetDefaultConfiguration()]. Requires machine keys
    user, email.
  - GetConfigValue precedence (section 6.3). If --debug, optimise forced False.
  - "reconfig"/"clean" are read then REMOVED from properties; debug/optimise/
    unsafe/profile persisted. Before reconfig, stale executables removed
    (exe/cactus_<config>, exe/<config>/).
  - OptionList: reuse stored unless --optionlist given. Build flags DEBUG/OPTIMISE/
    UNSAFE/PROFILE substituted (AddReplacement + SubAll) before compare/write.
    hasOutdatedConfig = no complete config OR no stored options OR stored != current.
  - Reconfigure (if outdated or --reconfig): compare the VERSION line of old vs
    new option list (regex r'^\s*VERSION\s*=\s*([^\n#;]*)$'); a VERSION change
    forces a FULL rebuild. Then (unless --virtual):
        cd <CACTUS_PATH> && echo yes | { <make> <config>-config options=<OptionList>; } 2>&1
    nonzero -> exit 1; remove config-data/make.thornlist.
  - Clean (unless --virtual): if requested or full-rebuild:
        cd <CACTUS_PATH> && <make> <config>-realclean 2>&1   (nonzero -> exit 1)
  - SubmitScript: --no-submitscript removes it (disables submission). Else copied
    from GetSubmitScript (optional; absence just disables submission).
  - RunScript: REQUIRED -- fatal if none stored and none available.
  - ThornList: REQUIRED. Content processed by GetThornListContents using
    enabled-thorns*/disabled-thorns* machine keys to toggle "#DISABLED " prefixes
    via regex.
  - BuildConfiguration: sets USER/EMAIL/ALLOCATION; MAKEJOBS = --makejobs option
    else machine 'makejobs' key else 1; make = SubAll(machine 'make'). Then:
        make <config>          ("Building %s")
        make <config>-utils    ("Building utilities...")
    each: cd <CACTUS_PATH> && <make> <target> 2>&1; nonzero -> exit 1.
    (ThornGuide doc build is commented out.) Parallelism is ONLY via @MAKEJOBS@ in
    the 'make' key; sim-build never passes -j directly.
  - BuildVirtual (--virtual): requires --virtual-executable; copies it to
    EXE_PATH/cactus_<config>; no configure/make.

17. SYNC SUBSYSTEM (lib/sim-sync.py)
================================================================================
"sim sync [machine...]" rsyncs the local Cactus source tree to remote machines.

Path selection: --sync-parfiles -> config 'sync-parfiles'; --sync-sourcetree ->
config 'sync-sources'; --sync-path <p> (repeatable) -> explicit; none -> BOTH
sync-parfiles and sync-sources. Machines = positional args (excluding 'sync');
none -> fatal. Cannot sync to the local machine.

Remote path: redirects to the IO machine (key 'iomachine') if set. Requires keys
user, allocation, sourcebasedir, hostname, rsynccmd, rsyncopts, sshcmd, sshopts.
  fullpath = "<user>@<hostname>:<sourcebasedir>/<local_suffix>"
where local_suffix = the relative path of CACTUS_PATH under the local source base
dir. Multiple explicit paths: only top-level names allowed (a path with a dir
component is fatal; a missing path is a warning).

Rsync flags (EXACT default set, sim-sync.py:134-147):
  --checksum --compress --delete --hard-links --links --partial --progress
  --recursive --sparse --stats --verbose
  (--perms and --times are intentionally OMITTED so the target recompiles changed
  files; --checksum compensates for the missing --times. --group/--owner/-D omitted.)

Filter rules: ruleFile = 'filter.rules' (or 'filter.prersync3.rules' for rsync
<3.0.0). Always "--filter 'merge <BASE>/etc/<ruleFile>'"; if
<BASE>/etc/filter.local.rules exists it is prepended as another merge filter.

Command assembly:
  <rsynccmd> --rsh=<sshcmd> --rsync-path=<entry rsynccmd> <defaults> <rsyncopts>
  <entry rsyncopts> <arguments> <rsyncfiles> <fullpath>
A remote "mkdir -p <sourcebasedir/local_suffix>" runs first (via GetSSHCommand on
the IO machine). The whole thing is wrapped:
  cd <local_sourcedir> && { <localsshsetup>; } && { <mkdircmd> && <rsync>; }
Old/new fallback: runs the modern command; if it exits 2 (protocol mismatch),
retries with the pre-3 rules.
  *** BUG: the final "Sync complete." vs "Errors occurred" decision checks only
     the LAST loop iteration's `ret`, not the accumulated `errors` (sim-sync.py:278). ***

18. REMOTE EXECUTION & SSH CONSTRUCTION
================================================================================
--remote short-circuits sim.py to RemoteExecute (sim.py:109-114): RequireMachine;
RemoteEnvironment.init(machine); ExecuteSameCommand(parrotArguments=True,
stripArguments=['remote','remotecactuspath','machine']).

RemoteEnvironment (simremote.py):
  - init: fatal if remote == local; requires remote keys envsetup, allocation,
    sourcebasedir, user, hostname. localEnvSetup = local 'envsetup' (USER subbed).
  - GetRemoteExePath: --remotecactuspath overrides; else remap CACTUS_PATH from
    the local source base dir onto the remote source base dir; build remotes/
    <suffix>/<exe>.
  - ExecuteSameCommand: re-emit positional args (QuoteSafe'd) + BuildOptionString
    (minus stripped keys) + "--machine=<remotemachine>", run over ssh, wrapped
    "{ <localEnvSetup>; } && { <localsshsetup>; } && <cmd>". ssh status high byte
    0xff -> fatal "Could not execute command".

GetSSHCommand (simlib.py:473-533): builds
  "<from_sshprefix> <sshcmd> <from_sshopts> <sshopts> <other_opts> <user>@<hostname> <QuoteSafe(cmd)>"
then SubAll. If a 'trampoline' is set, it recurses to tunnel through the
trampoline host. If cmd is None the user@host part is omitted (used as a plain
rsync --rsh prefix). QuoteSafe = "'%s'" % cmd.replace("'", r"'\''").

ExecuteCommand (simlib.py:535-584): prepends local 'envsetup' (USER subbed) and
runs `/bin/bash -c '<...>'`; output=False uses os.system, output=True uses
os.popen returning (output, ret).

19. ARCHIVE SUBSYSTEM (lib/simarchive.py + lib/archive/*)
================================================================================
SimArchive(driver, restart=None) (simarchive.py:12). Driver loaded by
eval("<archivetype>.Driver(self)"); archivetype is a machine key. Drivers:
'petashare' (iRODS/PetaShare) and 'uberftp' (GridFTP) (archive/__init__.py:2).

authenticate(): requires local key 'archiveuser'; driver.authenticate(username);
nonzero -> exit 1.
store(): requires 'archivebasepath'.
    dstPath = "<archivebasepath>/<simulationid>"
    whole sim (RestartID==-1): srcPath = SimulationDir
    one restart: srcPath = RestartDir; dstPath += "/output-<LongRestartID>"
get(simulationid, dstPath, restartid): srcPath = "<archivebasepath>/<simulationid>".
  *** BUG: forms the restart subpath from dstPath, not srcPath (simarchive.py:77,79). ***
listSimulations(): driver.list; keeps lines starting "simulation-"; canonical
  archived name format:
    simulation-<name>-<machine>-<hostname>-<user>-<date1>-<date2>
GetRestartsForSimulation: lists "output-" entries; id after the first '-'.

petashare driver: requires local 'archivetoolspath'; runs <tools>/<cmd> 2>&1.
  authenticate: pchangeuser <user> (prompts for password).
  store: pmkdir -p <dst>; prsync -rV <src> i:<dst>.
  get:   prsync -rV i:<src> <dst>.
  list:  pls <src>; keeps "C-" (collection) lines.
  *** lineToFile references an out-of-scope srcPath (would NameError if reached). ***
uberftp driver: requires local 'archivehostname'; runs
  uberftp <host> "quote wait; parallel 8; <cmd>" 2>&1.
  authenticate: grid-proxy-info -timeleft; else myproxy-logon -l <user>.
  store: repeated mkdir then "put -r <src>/* <dst>". get: "get -r <src> <dst>".
  list: "ls <src>"; keeps "d" (directory) lines.

User-facing: list-archived-simulations (sim-info), get-archived-simulation
(sim-util), and store() invoked by the restart lifecycle (sim archive).
  *** UNCERTAIN: sim-util get-archived-simulation calls SimArchive(simenv,
     archiveType) (sim-util.py:190) but __init__ is (driver, restart=None) and
     list-archived uses SimArchive(archiveType) (sim-info.py:48). One call site
     has the wrong signature; whether the get path works as written is unverified. ***

20. DECISION TREES: sim setup / setup-silent (lib/simdt.py + lib/dt/*.ini)
================================================================================
Purpose: interactively GENERATE etc/defs.local.ini and create a local machine
entry from generic.ini. Driven by lib/dt/*.ini:
  defaults.ini        -- `sim setup` (prompts).
  defaults-silent.ini -- `sim setup-silent` (no prompts; save=noprompt; uses
                         option:setup-user / option:setup-email / NO_ALLOCATION).
  machine-override.ini -- chained tree to append arbitrary mdb key/value pairs
                         under a named machine section.

Tree format: [decisiontree] (prompt, required, dest="ini:<relpath>", repeat,
repeatstatement, next="decisiontree:<name>", save); [<section>] (type=section,
fixed=yes/no); [action:N] (action=%MACRO()%, optional check, printresults);
[keyvalue:N] (key/value prompts/defaults/dests; valuedefault may be "%MACRO()%",
"@var@", or "option:<optname>"). Order encoded in the ":N" suffix.

Key macros: GET_LOCAL_MACHINE_NAME; CHECK_CREATE_MACHINE (true if machine absent);
CREATE_MACHINE (copies generic.ini -> <machine>.ini, renames the section, sets
name/hostname/nickname, sourcebasedir/basedir, optionlist/submitscript/runscript
if overridden, auto-detects ppn/num-threads via lscpu or macOS sysctl, handles
macOS gcc-vs-clang by rewriting the optionlist to a generic<suffix>.cfg copy);
GET_DEFAULT_USERNAME ($LOGNAME/$USER/passwd); GET_DEFAULT_EMAIL (git config
user.email if it has '@', else username); GET_BASEDIR (<home>/simulations);
GET_SOURCEBASEDIR (--setup-sourcebasedir or parent of CACTUS_PATH).

Output: writes etc/defs.local.ini [default] with user/email/allocation/
sourcebasedir/basedir, runs CREATE_MACHINE (guarded by CHECK_CREATE_MACHINE), and
optionally appends per-machine overrides.

21. DISTRIBUTE & BENCH TOOLS (bin/, standalone, Python 2)
================================================================================
These are test-harness CLIENTS of `sim`; they shell out to bin/sim
(--remote/--machine) and parse its textual output. They share the MDB/libs only
to read machine parameters, never to manipulate simulation state directly.

distribute (bin/distribute): for each machine, syncs, builds debug+production
(+aligned) configs from scratch, runs the testsuite, submits a test job, waits,
and can benchmark + recovery-test. Replaces libutil.fatal so a fatal does not
exit globally. Default machine set: db1, expanse, golub, osx-homebrew,
osx-macports, qb, qbc, shelob, smic, stampede2, stampede2-skx, summit,
supermuc-ng. Subcommands used: execute, sync, list-configurations,
list-simulations, purge, build, create-submit, submit, cleanup, show-output,
get-output-dir. Runs each target in the BACKGROUND (double fork + setsid);
stdout/stderr -> log/<machine>.out, results -> log/<machine>.results; output
prefixed "DISTRIBUTE:" with "[%Y-%m-%d %H:%M:%S]" timestamps. Build status from
list-configurations ("[built ...]"->S, "[incomplete]"->F); sim status from
list-simulations (INACTIVE->I, QUEUED->Q, PRESUBMITTED|RUNNING->R, FINISHED->F);
success from "^Done\.$" in show-output.

distribute-watch: a 60s monitor loop reading only log/*.out (does not touch remote
machines); prints a one-line-per-machine status table.

distribute-gather (bash): pulls testsuite results via `sim execute`/
list-simulations/get-output-dir; cats <outdir>/TEST/sim/summary.log between
markers; renames per-run logs to "<machine>__<procs>_<threads>.log".

bench-create (bin/bench-create.py): standalone benchmark generator. Sweeps the
cartesian product of physics params (hydro, multipatch, levels, fdorder) and
geometry (cores, ppn_used, threads, smt), sizing the grid to fill nodes*memory.
Emits per combination: "<path>/<filename>.par" (McLachlan/Carpet), "<exename>.th"
(thorn list), build/submit lines, with sim names formatted
  "<filename>-nodes%04d-cores%06d-procs%06d-threads%04d-smt%02d-run%04d".
Also writes build.sh, submit.sh, collect.sh (parses carpet-timing..asc column
$26), and simulations.txt (names between BEGIN_SIMULATIONS/END_SIMULATIONS).

22. LOGGING, ERRORS, EXIT CODES (lib/libutil.py)
================================================================================
  fatal(msg)   -> "Error: <msg>" + "Aborting Simfactory." to stderr, close log,
                  sys.exit(1). The universal error path.
  warning(msg) -> "Warning: <msg>" (always shown).
  info(msg)    -> "Info: <msg>" (only when --verbose).
  display(msg) -> always printed.
  Logging: messages go to <BASE>/../log/simfactory.log ("[LOG:<ts>] ..."). If the
  log dir can't be created -> exit 1; if the file can't be opened -> falls back to
  stderr (no abort). Before INITIALIZED, output goes straight to stdout/stderr.
  CoerceBool: false_values = ['False','false','No','no','F','f','0', 0, False,
  None, '']; True for anything else.
  Exit codes observed: 0 (help/no-args), 1 (essentially everything else, via
  fatal()/explicit exits). There is NO distinct exit code per failure class.

24. NOTES & RECOMMENDATIONS FOR THE REPLACEMENT
================================================================================
  - The on-disk contract (section 13) is the load-bearing interface. Anything
    that must interoperate with existing simulation directories MUST preserve:
    the SIMFACTORY/ metadata dir name, "output-%04d" restart dirs, the
    "output-NNNN-active" RELATIVE symlink as the single source of truth for "which
    restart is active", properties.ini under "[properties]", the simulation_id /
    pbsSimulationName format strings, CACHE/ and TRASH/ siblings, and the
    parfile-basename working dir inside each restart.
  - State is INFERRED, not stored: "active" = the symlink; job status = a LIVE
    queue query against the machine's *pattern regexes. There is no state-machine
    field. A replacement may store explicit state but must still recognize the
    symlink for compatibility.
  - Job-id lives in the 'jobid' property; job.ini is read-only legacy. SIMULATION_ID
    (file) marks simfactory-1 sims and is never written by simfactory2.
  - Several literal defaults (basedir, sourcebasedir templates; queue stdout/err
    filenames; checkpoint and Formaline tarball naming) come from OUTSIDE this
    Python: the machine DB, the submit-script templates, and Cactus/thorns at
    runtime. The Python only constructs templates and matches patterns
    ("*chkpt.it_*", "*.chkpt.tmp.it_*.*", "*.tar.gz", "formaline-jar.txt").
  - The @VAR@/@(...)@/@ENV()@ substitution engine and the MDB syntax-checked key
    catalog (section 8) are the other two hard interfaces: machine files, option
    lists, run scripts and submit scripts in the wild depend on exactly these.
